# Widget-RS 在线插件市场开发计划与落地方案

本文档详细规划 `widget-rs` 的**在线插件市场（Marketplace）**体系，明确社区开发者小组件的远端托管、自动化审查、在线分发、客户端下载安装、热更新与安全沙箱全生命周期方案，作为后续各迭代阶段的开发指导规范。

---

## 1. 架构定位与设计哲学

在 `widget-rs` 体系中，小组件采用双轨制运行，在线插件市场专注于**轻量级 JavaScript 动态扩展**：

| 类型 | 技术实现 | 运行环境 | 分发形态 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **原生插件 (Native)** | Rust + GPUI | 宿主进程原生执行 | 编译时静态链接注入 | 涉及深度 Windows API、底层钩子、高算力的核心功能（如桌面栅格、便签） |
| **JS 扩展 (Extension)** | JavaScript (ESM) + GPUI Shell | 嵌入式 QuickJS 虚拟机 | 在线动态分发（Zip 包） | 社区小组件、时钟、天气、番茄钟、股市监控、轻量资讯等（**市场核心**） |

### 设计目标
1. **零编译、免配置**：社区开发者只需前端 JavaScript 知识即可编写，普通用户一键“获取”即装即用。
2. **热插拔、免重启**：安装、更新、卸载全过程无需重启 `widget-rs` 主程序，窗口即时创建并挂载桌面。
3. **零运维、去中心化**：基于 GitHub 开源生态（类似 Obsidian / Raycast 模式），免去自建账户与中心数据库服务器的繁重维护开销。
4. **安全隔离、桌面穿透**：默认继承 `Progman` Win+D 置顶/置底穿透特性，同时通过 QuickJS 虚拟机与权限白名单隔离恶意系统调用。

## 3. 详细技术方案设计

### 3.1 远端插件索引协议 (`marketplace.json`)

官方维护一个集中式索引清单，托管于 GitHub Pages / Raw，结构定义如下：

```json
[
  {
    "id": "clock",
    "name": "极简时钟",
    "version": "1.1.0",
    "author": "widget-rs team",
    "description": "简洁优雅的桌面动态时钟小组件，支持秒针跳动与天气集成",
    "icon": "clock",
    "tags": ["时钟", "时间", "实用工具"],
    "min_app_version": "0.10.4",
    "homepage": "https://github.com/tierlabx/widget-rs",
    "download_url": "https://github.com/tierlabx/widget-rs/releases/download/v0.10.4/ext_clock.zip",
    "mirror_urls": [
      "https://cdn.jsdelivr.net/gh/tierlabx/widget-rs@main/extensions/clock.zip"
    ],
    "sha256": "8f462615...c1a92",
    "size_bytes": 15420,
    "permissions": ["network:fetch"]
  }
]
```

### 3.2 插件分发包结构规范 (`.zip`)

插件分发包必须为根平铺格式（或单层同名子目录），解压后必须包含：

```text
<plugin_id>.zip
├── manifest.json       # 必需：元数据与窗口基础属性定义
├── main.js             # 必需：ESM 逻辑入口（继承 gpui-kit View）
├── icon.png            # 可选：高清展示图标（建议 128x128）
└── README.md           # 推荐：插件使用与配置说明
```

### 3.3 本地存储与目录规范

严格遵守项目既定的 `widget_core::paths` 规范：

* **正式安装目录**：
  `%APPDATA%/tierlabx/widget-rs/extensions/<plugin_id>/`
* **临时下载与缓存目录**：
  `%APPDATA%/tierlabx/widget-rs/cache/downloads/`
* **市场索引本地缓存**：
  `%APPDATA%/tierlabx/widget-rs/cache/marketplace_cache.json`（设定 TTL 如 12 小时，避免每次切页重复请求）

### 3.4 下载与校验管道 (Download Pipeline)

1. **多源容灾（Dual-CDN Fallback）**：
   - 优先尝试直连 `download_url`（GitHub Releases）。
   - 若遇到连接超时或网络重置（常见于国内网络环境），自动回退至 `mirror_urls`（镜像节点）。
2. **SHA-256 完整性防篡改**：
   - 下载完成写入临时文件后，计算文件的 SHA-256 哈希值；
   - 只有与清单中 `sha256` 匹配时才进入解压环节，杜绝不完整包或运营商劫持注入。
3. **Zip Slip 安全防御**：
   - 解压每个条目时，必须通过 `canonicalize()` 严格验证目标路径属于 `<plugin_id>/` 目录内部，严禁通过 `../` 越界覆盖系统敏感文件。

### 3.5 免重启热插拔机制 (Hot-Plug & Reload)

利用现有的 [crates/app/src/plugin/extension_loader.rs](file:///f:/03_OpenSource/widget-rs/crates/app/src/plugin/extension_loader.rs) 与 GPUI Shell：

1. **安装生效**：
   - 解压完成后，执行 `JsPlugin::load_from_dir(&ext_path)`；
   - 调用 `PluginManager::register_external_plugins` 注册进插件列表；
   - 更新 `AppConfig` 与 `UIState`，将 `loaded = true`，触发回调开启窗口。
2. **在线更新**：
   - 先关闭对应小组件的宿主窗口；
   - 解压新文件覆盖 `<plugin_id>/`；
   - 重新装载并在原坐标位置重新打开窗口，保留用户原有配置。
3. **彻底卸载**：
   - 关闭小组件窗口；
   - 从 `PluginManager` 中注销并清理 UI 状态；
   - 安全删除 `%APPDATA%/extensions/<plugin_id>/` 目录。

## 4. 客户端界面改造方案 (UI/UX)

在现有 [crates/ui/src/pages/widgets.rs](file:///f:/03_OpenSource/widget-rs/crates/ui/src/pages/widgets.rs) 基础上进行升级：

### 4.1 分类与状态切换
- **Tab 栏细化**：
  - `全部`：展示所有小组件（含本地与线上推荐）。
  - `插件市场`：仅展示来自远端市场的社区扩展。
  - `已安装`：仅显示本地已装载的组件（原生 + 已下载的 JS 扩展）。
  - `JS 扩展`：本地发现的外部 JS 脚本。
- **状态感知操作按钮**：
  - 未安装：`【获取】`（点击变为带进度条/转圈的 `下载中...`）。
  - 已安装且版本最新：`【已安装】`。
  - 已安装但有新版本：`【更新 (v1.2.0)】`。
  - 扩展卡片右上方提供 `...` 操作菜单：包含 `卸载`、`打开本地目录`、`访问主页`。

### 4.2 错误与弱网状态处理
- 离线模式：若网络不通，优雅提示“网络未连接，已展示本地已装小组件”，提供“重试连接”按钮。
- 下载失败：提示友好的错误信息（如“下载超时，已尝试切换备用镜像”），并提供一键重试。

## 5. 实施路线图与里程碑 (Roadmap)

整个在线插件方案划分为 **4 个迭代阶段**：

### 阶段一：本地下载解压与热加载链路跑通 (MVP)
- **目标**：实现从任意指定网络 URL 下载一个扩展 zip 包，自动解压并在桌面上弹现。
- **工作项**：
  1. 在 `crates/core` 中引入 `ureq` 或 `reqwest`（轻量同步/异步 HTTP 下载）。
  2. 引入 `zip` crate，实现带 Zip-Slip 防御的解压器与 SHA256 校验函数。
  3. 在 `crates/core/src/js_plugin` 提供外部扩展的独立热插拔 API（`load_single_extension`、`unload_extension`）。
  4. 验证：打包一个示例 `clock.zip` 上传测试，通过 CLI 或测试按钮验证一键安装成功。

### 阶段二：市场索引协议与 UI 全生命周期贯通
- **目标**：在控制面板的小部件库中直观看到远端插件列表，完成一键获取、更新、卸载全闭环。
- **工作项**：
  1. 定义 `crates/core/src/marketplace/` 模块，包含元数据结构体与本地缓存机制。
  2. 改造 `crates/ui/src/pages/widgets.rs` 与 `widgets_card.rs`，支持卡片异步下载进度状态渲染。
  3. 实现版本比对算法（Semantic Versioning），准确识别“可更新”状态。
  4. 接入卸载与更新覆盖逻辑。

### 阶段三：社区自动化审查与公共仓库建设
- **目标**：正式上线 `widget-rs/community-plugins` 仓库，开放社区接收 PR。
- **工作项**：
  1. 创建 GitHub 官方仓库 `community-plugins`。
  2. 编写 GitHub Actions 工作流：
     - PR 自动检查：校验 `manifest.json` 格式完整性。
     - QuickJS 无头静态验证：在 Node/QuickJS CI 环境中尝试执行 `main.js`，验证无语法报错。
     - 自动打包、生成 SHA256，并将元数据追加到 `marketplace.json`。
  3. 完善面向社区开发者的文档与提交指南模板（`CONTRIBUTING.md`）。

### 阶段四：安全权限声明与网络加速体系
- **目标**：加强对社区代码的安全防护，优化国内外下载体验。
- **工作项**：
  1. 细化 JS 扩展权限系统：在 `manifest.json` 中声明 `permissions`（如 `network`、`storage`），并在 UI 安装确认中显式提示。
  2. 部署 GitHub Actions 自动同步至 CDN 镜像（如 jsDelivr / 国内对象存储回源），确保国内下载顺畅。

## 6. 关键注意事项与风险防控

1. **单文件行数限制遵守**：
   - 严格遵守项目规范（任何 `.rs` 文件不超过 400 行）。
   - 网络请求与解压逻辑独立为 `crates/core/src/marketplace/`（下设 `client.rs`、`installer.rs`、`schema.rs` 等），UI 交互独立为 `crates/ui/src/pages/widgets_market.rs`。
2. **UI 界面规则**：
   - 严格执行 **UI 页面禁用 emoji** 规则，所有卡片图标使用统一的 `gpui_component::IconName`。
3. **核心窗口能力保留**：
   - 从市场安装下载的所有 JS 扩展，必须统一经过 `WidgetWindow<JsWidgetContent>` 包装，严格继承 `Progman` Win+D 桌面绑定与亚克力透明直通特性。
