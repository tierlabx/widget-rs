# Folia 歌词：架构与 GPUI 渲染动效管线

本文档详细规划如何在 `gpui` 渲染框架下，复现 Folia-Major 中丝滑震撼的视效管线，包括逐字扫光、流光舞台背景与弹性物理切换动效。

---

## 1. 总体渲染架构与分层

小部件的视觉层次自底向上划分为四层：

```
+-------------------------------------------------------------+
| Layer 4: 控制层与信息浮标 (SMTC 状态/曲目信息/控制按钮/设置入口)   |
+-------------------------------------------------------------+
| Layer 3: 核心歌词层 (逐字染色高亮行 + 上下景深散焦上下文歌词)       |
+-------------------------------------------------------------+
| Layer 2: 动态微光颗粒/唱片旋转微动效 (Ambient Flow Mesh)          |
+-------------------------------------------------------------+
| Layer 1: 动态色盘流光舞台背景 (自适应封面提取色 + 动态高斯弥散)     |
+-------------------------------------------------------------+
| Layer 0: DirectComposition 硬件透明通道 (直通 Windows 桌面壁纸)    |
+-------------------------------------------------------------+
```

## 2. 核心算法一：GPUI 逐字卡拉OK平滑扫光

### 2.1 逐字时间切片与进度计算
对于一条逐字歌词行：
```json
{
  "text": "沉浸在桌面里的每一个音符",
  "words": [
    { "word": "沉浸", "start_ms": 1200, "duration_ms": 400 },
    { "word": "在",   "start_ms": 1600, "duration_ms": 250 },
    { "word": "桌面", "start_ms": 1850, "duration_ms": 500 },
    ...
  ]
}
```
当前播放时间戳为 $T$ 时：
1. 计算当前行累计渲染进度的精确水平像素偏移量 $X_{progress}$。
2. 通过 GPUI 的 `cx.text_system().layout_line(...)` 精确测量每个字符的起始与终止像素坐标 $[X_{start}, X_{end}]$。
3. 单词内部采用线性平滑插值：
   $$X_{progress} = X_{start} + (X_{end} - X_{start}) \times \frac{T - \text{start\_ms}}{\text{duration\_ms}}$$

### 2.2 遮罩渲染管线 (Dual-layer Text Masking)
在 GPUI 的自定义渲染元素（`impl Element for KaraokeTextElement`）的 `paint` 阶段：
1. **底层（未播文本）**：
   - 绘制半透明灰白色静态文本（如 `rgba(255, 255, 255, 0.35)`）。
2. **顶层（激活发光文本）**：
   - 使用渐变高光色（根据专辑色盘调配的明亮主色与纯白高光）。
   - 通过 `cx.with_mask(ContentMask { bounds: active_rect })` 将激活文本的绘制范围裁切至 $[0, X_{progress}]$。
   - 在边缘处叠加一个 8px 宽度的柔和光晕过渡，消除像素边缘锯齿感。

## 3. 核心算法二：流光动态舞台背景 (Dynamic Flow Stage)

在 Folia-Major 中，流体背景主要采用 WebGL 碎片着色器。在 GPUI 中，我们采用基于 GPU 径向渐变混色与高斯弥散的高效渲染策略：

### 3.1 封面色盘提取与调和
- 当切歌加载到新封面图像时，在后台线程使用色彩量化算法（如 `color-thief-rs` 或轻量八叉树）提取 3 个代表色：
  - **Dominant Color（主基调色）**：用于大范围漫反射渐变。
  - **Accent Color（强调光色）**：用于高亮区域律动。
  - **Muted Color（沉浸暗色）**：用于压制对比度，确保文字清晰可辨。
- 对颜色进行饱和度与亮度校准，防止过亮影响文字可读性，或过暗缺乏舞台感。

### 3.2 多层动态径向渐变混合
在背景层使用自定义 Canvas 绘制：
- 维持 3 个浮动的椭圆渐变光源（Light Orbs），各自遵循低频正弦/余弦轨迹（Lissajous 曲线）缓缓漂移。
- 结合音频音量均方根（RMS）或固定节奏节拍（Beat Pulsing），轻微呼吸缩放光源半径（$\pm 8\%$）。
- 背景层整体施加 40px~80px 的 Backdrop Blur，形成极其柔和深邃的流光质感。

## 4. 核心算法三：Spring 弹簧物理歌词切行

### 4.1 传统切行的问题
传统的固定线性动画在遇到快节奏歌曲时会机械生硬，而在慢歌时容易拖沓。

### 4.2 弹簧阻尼模型 (Underdamped Spring)
采用二阶弹簧阻尼振荡方程驱动当前高亮行的 Y 轴位移与缩放系数：
$$F = -k(x - x_0) - c \cdot v$$
- **刚度系数 $k$**：设定为 $220.0$（保证响应迅捷）。
- **阻尼系数 $c$**：设定为 $24.0$（轻微超调后迅速归位，带来灵动的吸附感）。
- **动效特征**：
  - **行高激活**：新激活的行从 `0.92` 缩放平滑过渡至 `1.08`，字重加粗，不透明度从 `0.4` 提升至 `1.0`。
  - **移出行过渡**：退出的上一行平滑缩小回 `0.95`，散焦模糊值增加，透明度回归 `0.35`。

## 5. 性能与功耗优化标准

1. **空闲态静止检测 (Zero-CPU Idle)**：
   - 音乐暂停或停止播放超过 3 秒时，停止背景光斑漂移动画，GPU 帧率归零，进入纯事件驱动模式。
2. **脏标记局部重绘**：
   - 仅在播放中当前行逐字扫光推进时请求帧重绘（`cx.request_animation_frame()`）。
   - 上下未激活的上下文歌词行保持静态 Layout 缓存，避免重复度量文本尺寸。
3. **内存控制**：
   - 封面图片缓存最大保留 5 张（LRU 策略），解析后释放原生原始字节，仅保留渲染纹理。
