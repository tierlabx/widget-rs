# 小组件规范 (Widget Specification)

本规范用于指导 Widget-RS 项目中小组件（插件）的设计、UI 样式与交互，确保系统内置组件以及第三方扩展组件保持高度一致的极简、沉浸体验。

## 1. 核心设计原则

* **高内聚低耦合**：业务逻辑应完全封装在小组件内部，减少对主框架状态的依赖。
* **沉浸极简 (Immersive & Minimalist)**：抛弃传统的应用窗口概念。**严禁在小组件内部自行渲染常驻标题栏（Header）**。
* **暗黑主题为主 (Dark Theme Priority)**：遵循主体 VoltAgent 的深空极客暗黑美学。建议使用 `rgb(0x101010)` 或 `rgba(0x050507, 0.95)` 等极深色调作为默认背景色（特殊小组件如“便签”可除外，但需保持纯净）。
* **无边框体验 (Frameless)**：小组件边框及拖拽等通用行为由框架层的 `WidgetWindow` 统一接管，小组件只需关注核心内容。

## 2. 窗口行为与布局

### 2.1 标题栏与拖拽
* **禁止自定义常驻拖拽条**：小组件处于工作状态时，应该是无任何冗余边框和标题的纯内容展示。
* **统一的编辑模式**：用户通过全局快捷键或托盘菜单进入“编辑模式”后，框架会自动在小组件上方渲染一条绿色的（`#00d992`）拖拽手柄。开发者只需在实现 `WidgetContent` 特征时提供 `drag_label`。

### 2.2 尺寸与边距
* **圆角 (Border Radius)**：建议统一使用 `6px` 到 `8px` 的圆角大小（例如 `rounded(px(6.0))`）。
* **内边距 (Padding)**：主要内容区与窗口边缘应保持至少 `8px - 12px` 的内边距。
* **最小尺寸 (Min Size)**：如果在特定状态下需要折叠，请确保展开与折叠过渡平滑。

## 3. 交互与动效

* **Hover 动效**：按钮和可交互元素应具有统一的悬浮反馈（通常是背景变亮，如叠加 `rgba(0xffffff, 0.1)` 或边框高亮）。
* **编辑/输入状态**：当用户进入文本编辑时，保持原生 `Input` 的外观或使用极简下划线/边框高亮，避免弹出新窗口。
* **配置入口**：小组件特定配置应尽量在主窗口（Main Window）的设置面板中完成，小组件界面上仅保留最核心的操作（如：添加、删除、勾选）。

## 4. 开发约束

1. **废弃代码清理**：所有未引用的资源、冗余逻辑或测试代码在提交前必须清理。
2. **单一职责**：一个 `view.rs` 超过 300 行时，请考虑将部分通用 UI 抽离到独立的模块中。
3. **清晰的模块划分**：
   * `lib.rs`：插件入口、注册信息
   * `model.rs`：数据状态与持久化逻辑
   * `view.rs`：界面渲染逻辑
