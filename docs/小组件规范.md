# 小组件规范 (Widget Specification)

本规范用于指导 Widget-RS 项目中小组件（插件）的设计、UI 样式与交互，确保系统内置组件以及第三方扩展组件保持高度一致的极简、沉浸体验。

## 1. 核心设计原则

* **高内聚低耦合**：业务逻辑应完全封装在小组件内部，减少对主框架状态的依赖。
* **沉浸极简 (Immersive & Minimalist)**：抛弃传统的系统应用窗口概念。无边框设计，由框架统一管理拖拽。
* **暗黑主题为主 (Dark Theme Priority)**：遵循主体 VoltAgent 的深空极客暗黑美学。建议使用 `rgba(0x10, 0x10, 0x14, 0.95)` 或半透明磨砂玻璃质感作为默认背景（特殊小组件如便利贴可支持专属多主题色卡切换）。
* **无边框体验 (Frameless)**：小组件外层边框及拖拽等通用行为由框架层的 `WidgetWindow` 统一接管，小组件只需关注核心内容。

## 2. 窗口行为与布局

### 2.1 标题栏与业务功能条
* **禁止自定义常驻系统拖拽条**：小组件在普通工作状态下，不应有厚重的系统标题栏。
* **业务极简功能条**：具有特定工具属性的小组件（例如 Windows 便签的色卡切换/插入图片，或桌面收纳的分类标签）允许内置高度小于 `32px` 的专属极简业务操作栏。
* **统一的编辑模式**：用户开启“编辑模式”后，框架会在小组件上方自动渲染一条绿色的（`#00d992`）拖拽手柄。开发者只需在实现 `WidgetContent` 特征时提供 `drag_label`。

### 2.2 全局磁力吸附与对齐
所有小组件无需额外代码，自动享有框架级窗口物理吸附能力：
* **屏幕边缘吸附 (Screen Edge Snap)**：在编辑模式下拖拽小组件靠近屏幕或多显示器工作区四边（小于 18px）时，自动精准贴边对齐。
* **组件间磁力吸附 (Component-to-Component Magnet Snap)**：拖拽小组件靠近其他已开启的组件时，自动在边缘相贴、左对齐、右对齐、顶对齐、底对齐处产生磁力贴合。
* **融入桌面与浮动模式 (Desktop Pinning & Floating)**：支持将小组件（如桌面收纳、便签）钉在桌面底层（作为壁纸级桌面部件，Win+D 不被隐藏），或作为普通/置顶浮动窗口。

### 2.3 尺寸与边距
* **圆角 (Border Radius)**：建议统一使用 `6px` 到 `8px` 的圆角大小（例如 `rounded(px(6.0))`）。
* **内边距 (Padding)**：主要内容区与窗口边缘应保持至少 `8px - 12px` 的内边距。

### 2.4 独立设置弹窗规范 (Settings Window Specification)
带有独立设置窗口的插件，须保证全局一致的视觉与交互体验：
* **窗口创建**：统一使用 `widget_core::default_settings_window_options(cx, initial_size)`。
* **外壳与标题栏**：统一由 `widget_core::render_settings_shell(title, content)` 接管，提供 46px 标准标题栏（左侧支持 Windows 原生无缝拖拽，右侧带标准关闭按钮）。
* **设计语言与调色**：
  * 背景底色：统一使用 GitHub Dark 沉浸深色 `rgb(0x0d1117)`，窗口边框 `rgb(0x30363d)`。
  * 区块标题：统一使用 `widget_core::settings_section_header("...")`（字号 12px，粗体，灰字 `#8b949e`）。
  * 设置卡片：统一使用 `widget_core::settings_card()`（卡片底色 `#161b22`，边框 `#30363d`）。
* **滚动行为**：滚动条由 `render_settings_shell` 内层统一处理，页面内容无需自行处理外层滚动。

## 3. 交互与动效

* **Hover 动效**：按钮和可交互元素应具有统一的悬浮反馈（通常是背景微亮 `rgba(0xffffff, 0.1)` 或边框高亮）。
* **平滑动画 (Smooth Animation)**：动态进度条、倒计时与过渡动效应采用连续浮点插值与高帧率微定时器（如 50ms），确保 60FPS 丝滑不卡顿。
* **快捷输入与管理**：
  * 待办类组件推荐顶部常驻快速输入栏，按 Enter 即时追加。
  * 收纳类组件推荐网格图标排布，支持点击原生打开与快速添加/移除。
* **配置入口**：小组件详细配置应在主窗口（Main Window）设置面板中完成，组件表面仅保留最核心的操作。

## 4. 开发约束

1. **废弃代码清理**：所有未引用的资源、冗余逻辑或测试代码在提交前必须清理。
2. **单一职责**：一个 `view.rs` 超过 300 行时，请考虑将部分通用 UI 抽离到独立的子模块中。
3. **清晰的模块划分**：
   * `lib.rs`：插件入口、注册信息与 `Plugin` trait 实现
   * `model.rs`：数据状态与持久化逻辑（通过 `AppConfig`）
   * `view.rs`：界面渲染逻辑（实现 `WidgetContent` 与 `Render`）
